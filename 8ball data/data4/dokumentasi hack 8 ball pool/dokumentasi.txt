### 🔥 TEMUAN PALING KRUSIAL

1. **Semua SharedPreferences di loQPY7 adalah NATIVE** — method di `ouc9R2` semuanya `native`. Tidak ada SharedPreferences Java.
2. **Native library yang digunakan adalah `libloader.so`** (6.04 MB) — di-load oleh `oQLNW6.xT9Oe5()`
3. **String decryption** via `jLKPr9.hY1Z05()` — mapping karakter diambil dari `ouc9R2.uGifl7()` (native juga)
4. **Login form tidak ditemukan di Java** — tidak ada EditText, Button, WebView, atau HTTP request di loQPY7
5. **Login KEMUNGKINAN BESAR ada di NATIVE (.so)** — baik validasi username/password langsung di native, atau login form dibuat secara native (via OpenGL/SurfaceView dari `libjarellgod.so`)

### 💡 KESIMPULAN AKHIR

**Login dan expired check ada di NATIVE CODE (.so), bukan di Java/Smali.**

Ini adalah proteksi level tinggi dari modder — mereka sengaja memindahkan semua logika login, SharedPreferences, dan string decryption ke native library (`libloader.so`) agar sulit di-reverse.

**Tapi bukan berarti tidak bisa di bypass.** Ada celah:
1. Native method tetap dipanggil dari Java via JNI — kita bisa **patch caller Java** sebelum native dipanggil
2. Atau **patch tEOi55** (bridge native) untuk return value tetap
3. Atau **patch langsung native .so** — replace string check di binary

**Kita butuh 1-2 file lagi** — file yang memanggil `oU1Aa9` atau `getExpTime` — untuk tahu persis di mana letak pengecekan login, lalu patch dari sisi Java.
